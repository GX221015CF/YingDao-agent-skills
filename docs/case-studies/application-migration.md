# 脱敏案例：应用同机跨账号迁移

证据性质为原项目历史接入报告及最终用户验收。本次Skill整理核对源码与记录，实际迁移次数没有增加。

## 目标与实现

原任务目标是把已有影刀应用保存成本地可追溯材料，接入另一个正常登录账号并验证可用性。项目形成了离线存档/恢复、限范围正常接口重建，以及完整工程实验接入等不同工具。

完整工程样本使用项目自有 `.ydnative` 容器，收录流程侧文件、源码、参数、元素库、图像库及已有资源。接入器先通过正常Studio接口在空目标创建流程和参数，再按准确工程结构写入已核对原生侧文件，正常重载并保存。实际产品归属由目标工程生成，流程ID和调用目标经过映射。

## 已验证层级

|阶段|历史证据|
|---|---|
|B端结构接入|7个流程，5个VisualFlow、2个CodeFlow，46节点、4参数，1处流程调用映射|
|文件与保存|29个原生文件，正常重载和保存，静态错误0，最终clean|
|普通元素|19个元素名称正常识别，定位摘要精确回读|
|单CodeFlow专项|另有受限单代码流程跨账号接入及一次预览通过，不能扩成其他入口已执行|
|最终样本结果|用户明确确认应用正常使用及改名部分，作为该样本应用验收依据|
|图像补充交付|21份原字节图像、18处引用对应，两枚原图标按用户明确决定排除|

早期结构报告当时没有运行完整业务；后续最终验收采用用户实测确认。Agent工具运行、用户实测和图像独立实验各自保留证据范围。

## 经验如何进入当前Skill

- 从准确应用身份、完整组成和来源字节开始，保存旧值及引用映射。
- 先评估已有工具支持范围，再选择当前正常产品入口、接口重建或获准实验文件接入。
- 将流程、代码、参数、变量、完整元素、资源、图像、依赖和路径作为整体清单。
- 创建成功后继续核对字段、保存、归属与实际结果，按已约定范围收尾。
- 缺件和用户例外分别记录，保持源端关闭功能的原态。

## 可复用限制

该迁移器含旧样本特定空流程证据和codec输入，要求空目标、支撑模板兼容，并限制全局及共享依赖。新应用必须先核验这些前提，必要时作最小适配，不能仅替换应用ID执行旧命令。

本案例验证同机跨账号样本，其他电脑的版本、依赖、浏览器集成、账号权限和本地文件另核。原生侧文件接入、自有存档和产品官方导入方式分别说明，仓库没有捆绑完整现场执行器或商业格式提取代码。
