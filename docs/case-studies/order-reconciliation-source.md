# 进阶案例：Excel 订单核查与对账

核验日期为 2026-11-14。本文件为新源端案例的脱敏复盘，保存在本地版本中，未推送。原始页面样本、练习台账、输入预期、应用配置、运行日志和结果文件保留在维护者本地工作目录，不纳入本仓库文件集或 MIT 再分发。

## 业务目标与判断

从练习 Excel 读取待核查行，在影刀练习商城按稳定订单编号查询，对照金额和状态，生成逐行结果、异常明细和汇总。页面查询与读取由原生 VisualFlow 执行，CodeFlow 只负责数据解析、精确匹配、Decimal 计算和生成报表。

相较固定填表，本案例需要在查询前识别输入问题、重复和冲突，在查询后确认结果范围并精确关联编号，同时保留全部差异原因。金额统计只覆盖已找到、可比较的唯一首项，重复项不再查询，未找到及查询失败的实际金额保持空缺。

## 冻结基准及实现

只读采样运行一次。原生读取取得首页十条订单，一个完整编号查询只返回对应一条记录，一个特定测试编号返回明确“暂无数据”，最后清空筛选并读取恢复后的首页，十条记录与初态一致。

正式比较程序实现前，冻结十条采样基准、采样时点、16 行练习台账、独立字面预期和 SHA-256 清单。预期根据已观察数据和本次业务规则明确列出，验收器没有导入待验收的对账算法。

专用应用保留空 main，新增 21 节点只读采样流程、28 节点正式核查流程及一个计算 CodeFlow。正式流程每次编号查询前都清空筛选，确认首页多页列表已恢复，再提交编号查询，有限读取结果。明确空表、未加载、加载中及未遍历分页分别处理。精确查询后结果为终页，才允许按编号匹配或记未找到。

CodeFlow 使用当前应用正常提供的运行环境和 Python 标准库，包括 Decimal、HTMLParser、zipfile 与 XML，无依赖安装。XLSX 以文本保存编号，生成报表时保持金额十进制表示。

## 实测结果

正式全批仅运行一次，引擎 completed，静态与运行错误均为零，约 119.658 秒。162 项独立核对通过，冻结文件摘要在运行后仍一致。

|最终分类|行数|
|---|---|
|一致|5|
|差异|3|
|未找到|1|
|重复|3|
|输入冲突|2|
|输入问题|2|
|合计|16|

三条差异分别为金额不同、状态不同、金额与状态均不同。三条重复保留来源行引用，两个冲突行均跳过查询，缺编号和坏金额各保留一条输入问题。九个唯一编号实际查询，八个唯一订单可比较，网页金额合计 325.96，预期合计 336.96，网页减预期为 -11.00。没有未预期的查询失败或待人工确认项。

影刀流程实际生成新的 Excel，包含汇总、16 行逐行结果和 11 行异常明细。验收核对了分类、全部原因、重复引用、原始输入、网页实际值、查询完整性以及工作簿中的实际单元格内容。

## 检查与修正

15 项相关离线测试通过，涵盖金额格式、精度、前导零、重复、冲突、多候选精确匹配、双重差异、明确空结果、未加载/分页未遍历、全局上下文失效、重复查询拒绝和汇总范围。

首次离线测试有两处测试夹具文件名复用错误，改用独立临时文件后通过。采样配置初填出现输出变量改名依赖导致的局部失败，先读回实际残留，再只修正失败块。显式空文本在当前表单回读中未保留，改为空字符串表达式并核验。上述问题均在真实运行前解决，没有消耗额外现场运行。

采样 74 项字段和正式流程 94 项字段完整回读，CodeFlow 源码与候选 AST 一致，运行后配置再次一致。创建流程调用两次、共三个流程，结构插入两次，字段填写五次，参数写入两次，代码写入一次。明确保存调用零次，两次运行分别自动保存本任务已知修改。最终应用 clean，没有未知运行。
