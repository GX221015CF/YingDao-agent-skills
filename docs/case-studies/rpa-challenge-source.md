# 新案例：RPA Challenge Input Forms 源端验证

核验日期：2026-11-14。性质：当前仓库版 Skill 的一次新源端使用案例；本文件仅本地保存，未推送。练习附件、站点脚本、应用原始配置和现场日志均保留在本地 work，不随本文件提交，也不纳入 MIT 许可。

## 目标与方法

读取当前站点练习 Excel，按标签/稳定属性定位随机变换位置的七个输入框，完成十轮后读取站点实际评分。不使用坐标、Computer Use、外部浏览器自动化或 HTTP 模拟提交。

本次使用的仓库 Skill 入口和参考没有改动。它支持需求拆解、实用型方案、前态保护、合批搭建、回读、运行预算和分层验收。它不包含现场客户端，因此不能将本次过程全部归因于仓库中已有执行能力。

|部分|本次实际作用|

当前接口不提供创建应用或新增元素能力，因而两项人工参与是实际接口边界。公司名元素最初匹配多个输入框，修正为稳定字段属性后才允许运行。

## 实现与输入

当前站点规则仍为十轮、七字段。练习文件一张工作表、十条记录；一列表头有尾空格，在身份核验时处理，记录值不改。

最终专用应用保留空 main 和一个显式运行的 VisualFlow：23 个节点、9 个已注册变量、0 个流程参数、0 个全局变量。使用原生 Excel 打开和行循环、原生网页绑定/刷新/点击/输入/文本读取，少量代码段只处理输入核验、初始状态和评分解析。未建立 CodeFlow，也未将 Python 浏览器脚本作为填写实现。

依赖为当前影刀及其内置 openpyxl 驱动和 Edge 正常集成；应用声明额外依赖为零，没有安装包。正常资源接口报告资源零，未主动增加图像模板、图标或语义功能；接口没有回报的元素内部截图不能据此认定全无。

## 首轮问题与修正边界

首轮输入节点采用 CDP、未先聚焦且不做值验证；用户观察到全选效果。数据与当前公开练习参考一致，节点输入快照也对应正确，但站点评分为零。因此问题定位于首轮输入动作配置未形成有效成绩。

改为普通模拟输入、先点击聚焦并核验实际值，次数设置为一；第二轮内增加正常刷新。修正没有改变数据、字段对应或选择器。不能仅凭前后对比断言底层确切是 CDP、焦点或次数中的哪一项单独导致。

初次 22 节点回读核对 198 项填写字段；修正后 23 节点核对 209 项，运行后再次一致。创建流程一次，插入两次（骨架及刷新节点），填写两次（初次及差异修正）；明确 app.save 为零，两次 app.run 自动保存已知本任务修改。

等待超时只查询原 run_id。一次本地等待参数错误在 Schema 校验时被拒绝，修正后才发送；没有因该错误重跑挑战。

## 源端停点与迁移限制

最终应用 clean，无未知运行。输入附件、两次运行、完整配置回读、元素摘要和环境说明已建立本地基线。没有导出/导入整个应用、接触第二电脑或推送远端。

本次是受控验证流程：输入路径和防重复证据写入路径是准确本地路径；下一批迁移需显式映射，不能直接重跑并覆盖已有结果。元素正常接口只返回名称、URL 和 XPath 摘要，不是完整原生元素 XML，因此本次基线不能冒充可直接导入的完整迁移包。

第二电脑的 Windows、影刀版本/账号权限、Edge 正常集成及 Agent 可达性仍需在下一批核验。源端通过不证明跨设备迁移通过。
