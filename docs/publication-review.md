# 版本管理文件集与私有同步边界

## 当前已确认范围

1. 用户已认可本地候选，两个 Skill 的范围和脱敏案例保持，不将图像核验扩大成完整应用分享。
2. 确认有权许可的自编代码、文档与合成材料采用[标准 MIT](../LICENSE)，第三方与商标边界见[许可说明](licensing.md)。
3. 已批准本地 Git 首版保存和同名私有 GitHub 仓库同步；不公开，不变更已有仓库可见性，不邀请其他账号。

本地候选的已有离线结果继续有效。许可和说明调整不改变工具功能；本批检查文件清单、链接、实际暂存及发送历史，不重跑业务流程。

## 文件集

版本管理以 public-files.json 的显式文件列表为准。该名称沿用候选版，不能理解成已经授权公开。未列出的文件不自动纳入提交或同步；核对实际暂存内容和待发送历史，不能只依据 .gitignore。

work/ACTIVE_TASK.md、检查点、验证回执以及 .local/source-ledger.json 等本地管理资料没有纳入公开范围。不要直接压缩整个项目根上传。

## 本版检查的含义

tools/check_repository.py 检查公开清单一致、路径和链接、工具导入范围，以及明显的私人路径和敏感内容模式。它不是完整秘密扫描器或权利审查器；测试中的合成数据仍需人工查看语义。

本批只进行私有版本保存与同步，不创建公开仓库、公开 Pages 或 Release。实际提交、远程可见性和 HEAD 由正常客户端核验，内部回执保留本地；不能将私有推送称为公开发布。

## 个人分工

项目发起人承担需求定义、方案取舍、现场反馈和使用验收；Codex 协助代码、配置、工具执行与证据整理。这里是项目说明，不是简历或效率营销。
