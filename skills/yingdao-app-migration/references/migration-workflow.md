# 应用迁移工作流

## 1. 先确定本批对象

记录源/目标账号的脱敏标识、设备、应用名和现场 app_id。分别说明同机跨账号、跨设备同账号、跨设备跨账号，以及整应用或选定流程。历史身份只作线索，实际用户归属须有正常产品或用户核验依据。

恢复已有任务的最新有效报告、操作记录和原 run_id。未知导出或写入查实际产物/目标后态，避免重复接入。已有源端通过结果直接复用，目标端验收另算次数。存在独立主任务时，专项修改与主状态归属按项目规则处理。

先定义交付方式、结果标准、允许的结构/文件修改、保存/重载、指定入口与运行预算。运行可能自动保存整个应用，写入工具也可能持久化，这些影响纳入已有批准核对。

## 2. 查已有实现，再查当前合同

按工具说明及源项目证据盘点可复用采集器、存档器、接入器和验证器，识别固定案例限制。当前 Schema 缺少导出、创建应用或完整元素读取时，保留这一准确缺口，同时检查其他获准路径。

|路径|适合条件|需核对|
|---|---|---|
|产品正常分享、导出与导入|当前版本及账号权限实际提供入口|携带保存版还是发布版、源码可见/可编辑、完整元素/资源、目标归属、是否联网或产生费用|
|正常接口采集与重建|工具能表达所需节点、字段、代码和参数|当前 Schema、完整实例表单、变量作用域、调用映射、元素能力缺口|
|已有自有容器及实验接入器|准确源材料和目标工程合同可确认，当前用户允许相应文件写入|版本、包格式、codec来源、支撑文件、固定样本条件、原生侧文件写入、重载/保存及失败残留|
|离线材料交付|当前只要求存档，或接入前有具体缺口|来源、完整性、字段映射、依赖与缺件，明确现场尚未执行部分|

只有当前实际界面或官方资料支持时才给菜单路径。缺入口时索取最小菜单文字或由用户正常导出，避免让用户寻找推测中的按钮。实际缺权限或格式合同才停止受影响动作。

## 3. 完整来源清单

|组成|最少记录与核对|
|---|---|
|应用|名称、app_id、账号/设备、版本、启动入口、加载/保存/运行状态及采集时点|
|流程|完整目录、flow_id、类型、顺序或分组、主流程、子流程调用、停用节点及控制结构|
|VisualFlow|完整节点与字段、实际输出槽、变量生产者/消费者、循环/IF/异常边界、未设置/null/空值/表达式|
|CodeFlow|完整源码与摘要、入口、参数、相对导入、资源/全局/动态引用及外部文件|
|参数与变量|In/Out/实际支持方向、type、kind、默认值和未设置语义、全局变量及作用域|
|元素|完整原生定义或产品载体，元素/分组ID与名称、框架、定位子树、共享库及覆盖层、截图/图标/语义引用|
|资源与图像|正常资源、元素内部图像、图像库、分组图标、远程引用、原字节和全部绑定|
|依赖|Python发行包/版本、运行时、内置或自定义指令、共享组件、浏览器扩展及目标账号权限|
|支撑及路径|工程支撑文件、输入/输出/临时目录、绝对路径、环境配置及需用户重新登录的系统|

正常资源列表为0仅支持该列表为空。完整元素定义仍可能包含截图或语义图。元素名称/URL/XPath摘要用于字段对照，不能据此生成丢失的完整原生元素。

读取分页要完成全部页或注明局部。响应含省略、截断或只有最后循环快照时保留范围限制。完整性声明需要独立核对，缺对象与未采集分别列出。

代码只作静态引用分析，避免执行源码来获取依赖。动态引用无法闭合时记录表达式、需要的对象及处理方案。正常取得完整XML时保留命名空间、未知字段与原字节来源，不能仅凭表面XML结构声称产品可加载。

## 4. 载体、切换与接收准备

在项目独立目录保存一次准确材料，摘要与清单回读。区分产品官方包、自有存档容器、离线恢复目录、重建候选和已经接入的应用。自有 `.ydtransfer`、`.ydnative` 需对应工具与适用合同。

来源材料已足以覆盖本批范围且目标接入依据明确后，才请用户切换账号。存在来源缺口时先保留A端，完成可独立准备的工作。账号切换后重新发现客户端及 Schema，正常确认B与A不同，记录脱敏依据。进程未变和本地目录不同各自只证明对应事实。

同机可复用获准的本地练习输入，目标输出使用新位置。其他电脑须携带准确输入、必要资源和迁移载体，核对Windows/影刀/Python/浏览器及扩展、依赖版本、账号权益与Agent可达性。登录通过正常产品完成。

## 5. 目标接入与映射

目标写前保存身份、目录/文件、流程/元素和clean/dirty前态。检查同名同用途对象及历史操作，避免覆盖未知工程。旧工具要求空主流程或空元素库时，先核验这些真实技术前置。

|映射|核验点|
|---|---|
|应用|源/目标app_id及归属证据，正式创建或接收方式|
|流程|源flow_id→目标flow_id，类型、启动入口、子流程调用目标|
|参数与变量|名称、方向、类型/kind、默认值、生产消费顺序与作用域|
|CodeFlow|源/目标摘要、明确修改的路径或配置、相对导入及支撑模板兼容|
|元素与库|完整定义、名称及ID映射、分组、共享库与覆盖层、实际定位字段|
|资源|原资源→目标文件或引用，截图、图像库、语义图及图标逐项绑定|
|环境|依赖/指令版本、输入/新输出路径和需用户正常登录的外部系统|

按当前工具合同依次创建结构、声明参数、绑定调用并填写字段。级联字段刷新后使用最新实例表单，消费Out值采用当前返回的属性引用。编码后的磁盘字段不直接作为API输入。

原生侧文件接入属于单独的文件写入方式，需准确源目标路径、格式及恢复材料，说明其与产品官方导入的关系。保持目标产品生成的账号归属，避免手工篡改归属元数据。

响应不确定先读状态。部分成功先定位已应用项，保留前态/回执，再做获准的最小修正。写后完整回读涉及字段，参数、引用与源材料逐项核对，按需保存和重载，重载后再次核验身份与字段。

## 6. 受控运行与收口

保留源端输入、独立预期及失败记录。运行前检查目标页面、依赖与路径，固定指定入口、新输出位置及次数。主流程、业务流程、采样流程各按实际授权处理，避免为补日志额外启动。

running、pending、active=true、run_succeeded=null继续按同一run_id有限查询。用户暂停或停止时按当前合同停止自主推进。只有明确结束且失败原因已定位、最小修正回读并符合剩余预算时才再运行。

验收实际工作簿/文件内容、来源对应、分类、金额口径、网页或业务结果，不能仅凭引擎无错误判断。共享数据变化保留前后证据及原预期，再决定本批能否判定。

结束核验目标clean/dirty和归属持久化，正常关闭重开或等效读取是否实施分别记录。仅在预期字段、保存、目标账号及结果达到用户范围后关闭。未覆盖设备、其他账号、AI、图片加载及通用逆向按真实状态留在报告中。
