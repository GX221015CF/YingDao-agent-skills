# 工具选路与历史能力

本表来自原应用迁移项目的源码与验收记录。文件名帮助在已有项目中定向查找。Skill文档不捆绑这些现场执行器，使用前核验文件、版本、当前合同、材料及授权。安装版另有本地来源索引时按需读取，仓库候选不依赖私人来源即可理解工作流。

## 工具类别

|实现|作用|关键边界|
|---|---|---|
|`yingdao_transfer.py`及`application_materials.py`|自有存档的export/inspect/restore/plan、组成与材料审查|主CLI历史版本0.29，主体为离线工具。restore输出新目录；complete声明和CLI退出成功都不认证目标已接入|
|`application_capture.py`、`source_capture_a.py`、`m0_source_transport.py`|离线响应组装、顺序采集合同、正常M0库级传输|A批只覆盖部分流程/代码/参数。库级适配的替身通过、已有正常客户端及具体现场采集分别记录|
|`component_restore.py`、`selector_capture.py`、`selector_bundle.py`|完整元素XML、固定依赖、共享库/覆盖层及图片材料适配|旧组件实现有限支持普通元素，表格、图片、复杂ID或依赖分支以准确版本为准|
|`selector_mapping.py`、`selector_rebind.py`、`container_bindings.py`、`restoration_rules.py`|映射与恢复规则、库/分组/共享层判定|离线槽位和声明不证明目标库存在、账号授权或真实加载|
|`selector_join.py`、`candidate_closure.py`、`element_json_candidate.py`、`element_json_join.py`|引用闭合、候选元素及组成接入审查|XML/JSON投影是有界格式适配，未知字段或动态引用需保留，候选尚需原生接受证据|
|`element_locator_compare.py`、`element_image_review.py`、`element_auxiliary_review.py`、`m0_selector_readback_compare.py`|定位、截图/图片、辅助字段及正常摘要比较|字段摘要、离线XML和实际运行命中分别验收|
|`studio_flow_cli.py`及`studio_flow_bridge.py`|限范围流程文件采集及正常接口新ID重建|早期样例支持空VisualFlow、日志/变量和无参数CodeFlow，后来增加有限参数调用对。任意节点不自动适配|
|`single_codeflow_mcp_capture.py`、`single_codeflow_cli.py`、`single_codeflow_import.py`|单CodeFlow专项迁移链|历史固定一个Bool In及PyMuPDF版本，要求引用闭合与空目标。源码绝对路径保留，实际运行另核范围|
|`native_project_bridge.py`配合已审查的`native_restore.py`|自有完整工程包检查、正常API创建结构、原生侧文件接入和重载/保存|旧证书样本、有codec及特定空流程证据，目标空main/空库、支撑文件与共享/全局约束。原生文件写入需要单独计入影响|
|`restoration_session.py`、`writeback_contract.py`、`readback_preflight.py`等|操作会话、写入合同和回读审查|记录或计划已生成不等于其中的目标动作已经执行|
|本仓库`tools/migration.py`|组成声明、资源摘要和共享绑定离线核验|示例主要演示semantic.image材料。现场应用采集、容器恢复和接入需其他实现|

上述模块间的具体导入与调用以源码为准。需要适配时读取主入口、直接依赖、准确请求Schema和最近测试，避免执行旧固定批次或加载不明codec。

## 四种产物与接入结果

|对象|可说明的事实|下一项需要的证据|
|---|---|---|
|自有存档容器|登记的材料、原字节与摘要自洽|来源完整性及适用接入器|
|离线恢复目录|材料已恢复到本地新位置|当前影刀能正常接收该组成|
|重建候选|映射、字段与写入计划已准备|正常目标写入与完整回读|
|产品官方包|当前产品生成的指定载体|目标账号正常接收、权限、编辑及运行|
|实验接入后的工程|具体工具实际创建/写入并加载保存的目标对象|本批目标结果和持久化归属|

`.ydtransfer`与`.ydnative`为历史工具自有格式。官方`.bot`调用链曾在历史版本有界静态审查中定位，实际菜单可见性、账号权益和新版本导入仍需现场核验。

## 历史实测层级

|记录|已取得证据|适用限制|
|---|---|---|
|早期离线工具0.3及后续组件审查|存档、恢复、元素/依赖及引用逻辑的合成检查|离线结果不认证当前来源或目标接入|
|限范围流程往返实验|同账号测试应用内三流程采集、文件化、新ID重建及指定入口运行|范围内节点与参数组合，未覆盖任意应用|
|单CodeFlow同机跨账号样本|代码/参数/依赖回读及一次预览结果通过|特定代码与数据，其他流程/元素及改名分支按各自证据判断|
|完整七流程样本的B端结构接入|7流程、46节点、4参数、调用映射、原生文件重载/保存及19元素摘要精确回读|具体版本与空目标；该批未执行完整业务|
|样本最终验收及图像补交付|用户确认应用可用，21份图像与18处引用交付，两个原图标按明确决定排除|用户实测与Agent运行分别记账，排除只适用当次样本|
|新的订单核查源端|16行及独立预期、原生查询与Decimal报表验收通过|源端成功仍需本次B账号或其他设备独立验收|

历史报告中的`ready_for_import=false`、`full_reverse_complete=false`解释其当时能力范围。新样本是否完成按本批验收判定，不能机械沿用历史布尔值，也不能因样本通过将通用能力标为完成。

## 适配判断顺序

1. 确认工具来自用户认可的项目和准确版本，读主入口及直接相关依赖，识别是否含源样本ID、固定文件、节点、参数或运行门。
2. 列本批源组成与工具实际支持的交集及缺口。把获取完整材料、生成包、目标接入和运行分别判断。
3. 优先复用适配部分，必要时在本批项目内最小修改并验证。正常接口缺字段时，评估获准工程读取或产品菜单，避免只重复读取同一摘要。
4. 若当前明确禁止原生侧文件写入、codec或某读取方式，相关旧工具暂不适用。继续其他准备，并报告准确对象和能力缺口。
5. 接入和运行按当前身份、前态及授权实施。历史命令、`--execute`参数和代码中的允许开关均不产生授权。
