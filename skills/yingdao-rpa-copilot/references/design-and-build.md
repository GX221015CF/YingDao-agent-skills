# 需求设计与搭建准备

## 先确定最小可用范围

记录目标、输入样本、输出、业务键、数据量、频率、异常、不可改内容和验收方式。只追问会改变实现或风险的缺口。Demo、实用型和生产级按错误代价、值守、恢复能力选择，不按任务名称机械定级。

界面交互和主流程优先原生节点；Python 用于有收益的确定性算法。每个子流程说明输入、输出、依赖、逻辑、接入位置、失败处理和测试方式。

## 候选准备

从正常接口当前 Schema 和实例表单取得字段依据，不把旧响应直接当作写入请求。先规划控制流、参数、变量和引用，再生成候选。

- 循环、IF/Else 与结束节点闭合。
- 变量生产者先于消费者；输出槽和作用域正确。
- 行内元素在当前行父范围查找，页面刷新后按实际需要重新取元素。
- 需要改名时仅处理语法中的变量标识，不替换引号内业务文本或属性名。
- 未设置、null、空文本、字面量、表达式保持区别。
- 级联参数以已声明的目标参数和当前表单为准。

本仓库局部 Schema 校验不覆盖上述全部语义。六节点方法可辅助准备候选，不能解释为客户端接受了请求。

## 实施前的交付

说明目标、旧/新配置、依赖、预期影响、持久化可能、操作次数、通过标准和停止条件。先保存准确前态和恢复依据。未知能力明确为缺口，选择专项验证或人工补齐，不编造可见标签。
